# Архитектура

Один веб-сервис Django и общая база. Публичный рейтинг и личный кабинет — разные URL и разные очереди Celery.

```text
браузер
  │
  ├─ /            публичный рейтинг
  ├─ /repos/…     карточка, Markdown, повторный анализ
  ├─ /me/         Я ID, PAT, свои репозитории
  └─ /api/v1/     JSON каталога
        │
        ▼
   Django  ── Postgres (репозитории, сканы, метрики, баллы, находки)
        │
        ├─ Redis: брокер Celery, кэш дерева файлов, лимит 100 запросов/с
        │
        ├─ очередь analysis.scheduled
        │     каталог, beat, плановый скан четырёх публичных категорий
        └─ очередь analysis.user
              проверка доступа, затем анализ по кнопке:
              те же категории плюс CI, AppSec и git clone.
```



## Сборка и процессы

Локально `docker compose up` поднимает:


| Сервис                         | Роль                                     |
| ------------------------------ | ---------------------------------------- |
| `web-repo-health`              | Django, `runserver`                      |
| `postgres-repo-health`         | База                                     |
| `pgbouncer-repo-health`        | Пул соединений для воркеров              |
| `redis-repo-health`            | Брокер, результаты Celery, кэш           |
| `celery-scheduled-repo-health` | Очередь `analysis.scheduled`, пул gevent |
| `celery-user-repo-health`      | Очередь `analysis.user`, пул gevent      |
| `celery-beat-repo-health`      | Расписание                               |


Прод-файл `docker-compose-server-prod.yml` запускает web через gunicorn. Порты Postgres, Redis и web снаружи смотрят только на localhost.

Запуск с нуля описан в [README](../README.md). Формула — в [scoring.md](scoring.md).

## Данные одного анализа

Один репозиторий — один активный `Scan`. Пока скан в ожидании или в работе, вторую задачу не ставят. Личный запуск сначала занимает проверку доступа: на один репозиторий такая проверка тоже одна. Повторное нажатие в это время ничего не ставит.

Категории одного скана идут параллельно, группой Celery. Лимит запросов отдельный у трёх клиентов: API SourceCraft, raw-файлы и AppSec. У каждого потолок 90 запросов в секунду, это запас от 100. Перед вызовом клиент отмечает его в своём счётчике Redis и, если бюджет доли секунды выбран, ждёт. Если платформа ответит 429, HTTP-клиент повторит запрос и выждет столько, сколько сказано в заголовке Retry-After. Если повторы не помогли, Celery через 30 секунд заново ставит задачу категории. Пустой ответ не записывается как ноль.

Публичная цепочка: документация, состояние кода, активность и issues, затем агрегация. CI и Security сразу записываются как «Нет данных». Issues запрашиваются всегда: пустой список или ошибка чтения дают категории «Нет данных», а не ноль.

Личный запуск начинается с проверки, что PAT видит репозиторий. Ответ 403 или 404 снимает связь пользователя с репозиторием, скан не создаётся. Если платформа не ответила, проверка повторяется. После подтверждения цепочка клонирует ветку по умолчанию и добавляет CI и Security. Клон кладётся в `/tmp/repos/<id скана>`. Одновременно клонируются не больше четырёх репозиториев, один clone ждёт не дольше трёх минут. Если clone не удался, остальные категории всё равно идут: часть метрик останется без git-истории. Каталог клона не удаляется в момент окончания скана. Его снимает очистка: вместе с зависшими сканами каждые 20 минут и отдельным проходом каждый час. Живой скан не трогает. Кэш дерева файлов в Redis сбрасывается в конце цепочки. Исходники дольше этого не хранятся.

Агрегация пишет итог в `Repository.health_score` и пересчитывает у находок ожидаемый прирост общего Score. Если хеш ветки по умолчанию совпал с прошлым успешным сканом, плановый прогон новый `Scan` не создаёт. Кнопка анализа передаёт `force` и пересчитывает даже без нового коммита.

Кнопка есть только у пользователя, которому репозиторий доступен. Чужую публичную карточку так не пересчитать: её обновляет расписание. Служебный адрес `?scan=true` на карточке ставит публичную цепочку без CI и AppSec.

На публичной карточке и в подсказке рейтинга строки CI/CD и Security скрыты. Они видны, если карточку открыли из «Моих репозиториев» при сохранённом доступе, или если репозиторий не публичный. Число в рейтинге — итог последнего успешного скана целиком. Личный скан публичного репозитория включает в это число CI и Security, пока его не сменит следующий плановый успех. Выгрузка Markdown берёт тот же скан, что карточка, и перечисляет все категории, в том числе скрытые на публичной странице. Пока идёт проверка доступа или скан, файл не отдаётся.

Зависший скан (дольше `SCAN_STALE_TIMEOUT_MINUTES` в ожидании или в работе) переводится в ошибку. Проверка доступа, которая висит дольше того же порога, возвращается в обычное состояние с текстом ошибки. Если воркер упал ещё до старта цепочки, ожидающий скан тоже помечается ошибкой, и карточка не остаётся на «Идёт анализ». Незавершённый AppSec оставляет категорию «Безопасность» пустой, см. методику. Закрытую карточку страница проверяет коротким запросом к SourceCraft. Если проверка доступа или скан уже идут, этот запрос не делается.

## Источники данных

Готовых выгрузок нет. Всё читается из API и git SourceCraft токеном команды (каталог и публичный скан) или PAT пользователя (свой репозиторий).


| Источник                                         | Зачем                                                                              |
| ------------------------------------------------ | ---------------------------------------------------------------------------------- |
| `GET /repos`                                     | Каталог публичных репозиториев, курсор, пачками                                    |
| Карточка репозитория, дерево файлов, текст файла | Документация и состояние кода                                                      |
| Issues и события issue                           | Категория Issues                                                                   |
| Merge request, релизы                            | Активность                                                                         |
| `cicd` прогоны и `.sourcecraft/ci.yaml`          | CI, только со своим PAT                                                            |
| AppSec `GET /v1/scans/latest`, defect-groups     | Security, только со своим PAT. `gitRepo` — идентификатор репозитория в SourceCraft |
| Git clone ветки по умолчанию                     | Коммиты за 30 дней и давность TODO, только личный скан                             |
| Список доступных пользователю репозиториев       | Кабинет `/me/`                                                                     |
| Я ID, OAuth                                      | Кто вошёл. Токен Я ID не заменяет PAT для CI и AppSec                              |


Лимит 90 rps считается отдельно для API SourceCraft, raw-файлов и AppSec. Токен команды и PAT в git не коммитятся. PAT в базе хранится в зашифрованном поле профиля.

Закрытый репозиторий обрабатывается только в правах вошедшего пользователя и в выборку публичного рейтинга не входит. Стать private значит исчезнуть из списка: наружу история его сканов не отдаётся.

## Масштабирование

Каталог и пересчёт разведены по времени: обход раз в 12 часов, Score раз в 6 часов. Страница рейтинга пагинируется и не читает весь каталог в память. Обход каталога тоже идёт страницами и не держит все репозитории сразу.

Неизменившийся коммит не запускает повторный сбор. Дерево файлов на время скана кэшируется в Redis, чтобы шесть категорий не качали его по отдельности.

Воркеры уже два: долгий обход не стоит в одной очереди с кнопкой «Запустить анализ». Горизонтально добавляется ещё один процесс `celery worker` на ту же очередь. Postgres снаружи закрыт pgbouncer. Крупный репозиторий на публичном скане не клонируется: состояние кода смотрит дерево и не больше 30 файлов на TODO. Полный clone остаётся на одиночном личном запуске.

## Ограничения

- Публичный Score не включает CI и Security: сервисный токен эти данные чужого репозитория не запрашивает.
- В таблице рейтинга есть язык, Score, рейтинг SourceCraft, реакции, дата активности репозитория и дата проверки. Отдельной колонки места и отдельной сортировки по лайкам нет. Сортировки: Score, рейтинг платформы, активность, имя. Сортировка по Score пересчитывает итог последнего успешного скана той же формулой, что и колонка: вес категории умножается на полноту данных. Покрытие ниже половины базового веса сортируется как «нет данных». Частичный скан в рейтинг не попадает: и колонка, и сортировка смотрят последний успех.
- Контрибьюторы в балл активности не входят.
- Репозиторий только из данных получает низкий балл структуры, но итог не обнуляется. У пустого репозитория и у репозитория без ветки итог «Нет данных»: измерить категории нельзя.
- Список issues запрашивается на каждом скане. Пустой ответ или ошибка чтения оставляют категорию «Нет данных». Ноль открытых задач при непустом списке — измеренный результат, не пустая категория.
- Плановый проход ставит в очередь все публичные репозитории, у которых нет активного скана, а не фиксированную пачку. Лимит 90 rps на каждый клиент и пропуск неизменённого коммита этот поток сдерживают.
- Выгрузка отчёта — Markdown.
- Клон на gevent-воркере. Долгий git на личном скане занимает слот этого воркера. Одновременно идут не больше четырёх clone, каждый с ожиданием до трёх минут.
- Исходный код с внешних Git-платформ не импортируется.



## Что сделано сверх обязательного минимума

История последних сканов со статусом успех или частичный результат показывается на карточке: дата и итог, до 12 записей. Это не отдельный график позиций в рейтинге и не сравнение двух проектов.

В Issues уже есть доля зависших задач, медиана до первого ответа и медиана до закрытия. Разбора review-комментариев, карты владельцев файлов и bus factor нет.

`/api/v1/repos/` отдаёт публичный каталог и последний Score в JSON. Виджета и badge для README нет.

## Внешние сервисы и AI

Используются API SourceCraft, raw SourceCraft, AppSec SourceCraft, git SourceCraft и OAuth Я ID. Других внешних аналитических сервисов нет.

Клиент raw SourceCraft (`GET /raw/{org}/{repo}/{revision}/{path}` на `raw.sourcecraft.tech`) читает текст файлов публичного репозитория. Git clone для чтения файлов есть только у личного запуска: на публичном скане клона нет.

Балл и находки собираются правилами из фактов, которые вернули API, дерево файлов и текст файлов.
