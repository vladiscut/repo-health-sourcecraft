# Repo Health

Веб-сервис оценки здоровья репозиториев SourceCraft. Считает **Repo Health Score** от 0 до 100, объясняет балл по шести категориям и отдаёт приоритизированные рекомендации.

Тимлид, maintainer и владелец проекта видят один балл, из каких категорий он сложился и что поправить в первую очередь. Платформа SourceCraft получает регулярную оценку открытых репозиториев: по мере роста каталога их состояние остаётся сопоставимым в публичном рейтинге.

Стек: Django, шаблоны, Django REST framework, Postgres, Redis, Celery.

Методика: [docs/scoring.md](docs/scoring.md). Архитектура, API и ограничения: [docs/architecture.md](docs/architecture.md).

## Публичный стенд

Сайт уже работает: [https://repo-health.ru/](https://repo-health.ru/)

На главной — рейтинг открытых репозиториев SourceCraft. Найдите нужный по названию, выберите ЯП или поменяйте сортировку и откройте строку. На странице репозитория видно общий балл, из каких частей он сложился и что стоит поправить. Отчёт скачивается кнопкой «Скачать Markdown».

Свои репозитории открываются после входа. Нажмите «Войти через Я ID» и подтвердите вход аккаунтом Яндекса. Откроется раздел «Мои репозитории». Вставьте туда персональный токен SourceCraft (PAT) и сохраните его. Появится список репозиториев, к которым есть доступ с этим PAT, в том числе приватных. У нужного нажмите «Анализировать». Сервис сначала ещё раз проверяет, что PAT видит репозиторий, затем считает все шесть категорий, включая CI и безопасность. Эти две категории видны на карточке, открытой из «Моих репозиториев». Приватный репозиторий в общий рейтинг не попадает.

Кнопка «Выйти» в шапке завершает сессию.

## Как поднять локально

Нужен Docker.

```powershell
copy .env.example .env
docker compose up --build
```

Откройте [http://127.0.0.1:8002/](http://127.0.0.1:8002/)

В `.env` заполните токены.

`SOURCECRAFT_API_TOKEN` — токен SourceCraft, с ним сервис загружает каталог открытых репозиториев. Без него список на главной останется пустым.

Вход через Я ID включается данными приложения с [oauth.yandex.ru](https://oauth.yandex.ru/). Это настройка самой авторизации, её делает тот, кто поднимает сайт:

- `YANDEX_CLIENT_ID` — ID приложения
- `YANDEX_CLIENT_SECRET` — секрет приложения
- `YANDEX_REDIRECT_URI` — адрес, на который Яндекс возвращает браузер после входа. Для локального запуска оставьте `http://127.0.0.1:8002/auth/yandex/callback/` и укажите этот же адрес в настройках приложения

Персональный токен SourceCraft каждый вводит сам на сайте, в разделе «Мои репозитории», уже после входа.


| Адрес                  | Что там                                                                                                                               |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------- |
| `/`                    | Публичный рейтинг, по 50 репозиториев на страницу. Колонки: язык, рейтинг SourceCraft, реакции, дата активности, дата проверки, Score |
| `/repos/<org>/<repo>/` | Карточка: Score, из чего он сложился, рекомендации с приростом к итогу, выгрузка Markdown                                             |
| `/me/`                 | Вход через Я ID, PAT SourceCraft, свои репозитории                                                                                    |
| `/api/v1/repos/`       | JSON публичного каталога, тоже по 50                                                                                                  |
| `/admin/`              | Django admin                                                                                                                          |


Остановить: `Ctrl+C` или `docker compose down`. База остаётся в томе `postgres-repo-health-volume`.

Первый запуск, если таблица репозиториев пустая, запускается celery задача, которая получит каталог публичных репозиториев. Страницу списка можно открыть сразу: она не грузит всю таблицу.

## Два контура

Плановый скан публичного репозитория считает документацию, активность, issues и состояние кода. CI/CD и Security не запрашиваются и записываются как «Нет данных», их вес переходит к категориям, где балл есть. Подметрики, которым нужен git clone, на публичном скане не считаются.

Кнопка «Анализировать» в «Моих репозиториях» и «Запустить анализ» на карточке есть только у пользователя, которому репозиторий уже доступен. Нажатие не создаёт скан сразу: воркер проверяет, что PAT ещё видит репозиторий, и только потом ставит полный анализ, включая CI, AppSec и git clone. Пока идёт проверка, на карточке написано «Проверяем доступ к репозиторию…». Повторное нажатие, пока проверка или скан уже идут, вторую задачу не ставит. Чужой публичный репозиторий с карточки так не пересчитать: его обновляет задача по расписанию.

На публичной карточке и в подсказке рейтинга строки CI/CD и Security скрыты. Они показываются, если карточку открыли из «Моих репозиториев» и доступ сохранён, либо если репозиторий не публичный. Число Score в рейтинге — итог последнего успешного скана. Если это был личный анализ публичного репозитория, в числе уже есть CI и Security, пока следующий плановый скан не заменит результат. Закрытый репозиторий в публичный список не попадает.

Лайки в формулу Score не входят. Они остаются колонкой реакций в рейтинге.

## Расписание

Celery beat (`celery-beat-repo-health`):


| Задача                                | Когда                            |
| ------------------------------------- | -------------------------------- |
| Обход каталога публичных репозиториев | каждые 12 часов, в 00:00 и 12:00 |
| Плановый пересчёт Score               | каждые 6 часов, в :30            |
| Снятие зависших сканов                | каждые 20 минут                  |
| Удаление осиротевших каталогов клонов | каждый час                       |


Повторный плановый скан пропускает репозиторий, если хеш ветки по умолчанию не изменился и уже есть завершённый скан. Зависшим считается скан, который дольше `SCAN_STALE_TIMEOUT_MINUTES` остаётся в ожидании или в работе.

Проверить beat: `docker compose logs celery-beat-repo-health`.

Очереди разделены. Плановый обход слушает `celery-scheduled-repo-health` (`analysis.scheduled`). Нажатие «Запустить анализ» на своём репозитории уходит в `celery-user-repo-health` (`analysis.user`).

## Если страница пустая

1. `docker compose ps` — web, postgres, pgbouncer, redis, оба воркера и beat в состоянии running.
2. Нет репозиториев на `/` — пустой `SOURCECRAFT_API_TOKEN` или каталог ещё не дошёл. Логи: `docker compose logs celery-scheduled-repo-health`.
3. На публичной карточке нет строк CI и Security — так и задумано. Они появляются, если открыть репозиторий из «Моих репозиториев» после анализа со своим PAT.
